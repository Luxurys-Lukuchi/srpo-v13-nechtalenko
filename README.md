## Описание предметной области и контракта

Предметная библиотека (`include/`, `src/`) обрабатывает код обозначения фиксированного формата: две заглавные латинские буквы (`A-Z`), дефис (`-`), четыре десятичные цифры (`0000..9999`), например `AB-1234`. Вход — одно поле без пробелов.

**Четыре операции библиотеки:**
1. Буквенная часть (`AB`).
2. Числовая часть как целое число (`0..9999`).
3. Строка кода с числом ровно из четырех цифр (с ведущими нулями).
4. Следующий код (числовая часть увеличена на 1).

**Условия отказа:**
- пустой ввод или наличие пробелов;
- строка не подходит под формат `LL-DDDD` (неверная длина, строчные или нелатинские буквы, отсутствие дефиса, нецифровые символы);
- запрошен следующий код после `9999` (переход через `9999` не определен).

Все вычисления и формирование текста отказа выполняет библиотека (`include/`, `src/`). Консольная оболочка (`apps/cli/`) только читает одну строку, вызывает библиотеку и печатает результат.

## Сборка и запуск

Бинарные файлы сборки (`*.exe`, `*.o`, каталог `build/`) в дереве исходников не хранятся и перед сдачей удаляются.

**Сборка Debug:**
```powershell
mkdir -Force build
g++ -std=c++17 -Wall -Wextra -Wpedantic -g -O0 -Iinclude apps/cli/main.cpp src/designation_code.cpp -o build/app_debug.exe
```

**Сборка Release:**
```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic -O2 -DNDEBUG -Iinclude apps/cli/main.cpp src/designation_code.cpp -o build/app_release.exe
```

**Запуск:**
- интерактивно (программа выводит приглашение со справочным примером): `.\build\app_debug.exe` или `.\build\app_release.exe`;
- с передачей строки через конвейер: `"GH-0001" | .\build\app_debug.exe`.

### Режимы Debug и Release в данной сборке
- **Debug (`-g -O0`):** отключает оптимизацию и включает отладочную информацию в исполняемый файл; проверки `assert` сохранены. Используется для отладки и поиска дефектов.
- **Release (`-O2 -DNDEBUG`):** включает оптимизацию кода и задает макрос `NDEBUG`, который убирает проверки `assert` на этапе препроцессинга. Итоговый файл меньше и работает быстрее; используется для поставки и замеров скорости.

## Фактические прогоны

### 1. Корректный вход (`GH-0001`, интерактивный запуск)
```powershell
PS> .\build\app_debug.exe
Введите код обозначения (формат LL-DDDD, например AB-1234): GH-0001
1. Буквенная часть: GH
2. Числовая часть: 1
3. Строка кода: GH-0001
4. Следующий код: GH-0002
```

### 2. Отказ: неверный формат (`4`)
```powershell
PS> .\build\app_debug.exe
Введите код обозначения (формат LL-DDDD, например AB-1234): 4
Отказ: неверная длина кода (ожидается ровно 7 символов в формате LL-DDDD).
```

### 3. Отказ: переход через `9999` (`ZX-9999`)
```powershell
PS> .\build\app_debug.exe
Введите код обозначения (формат LL-DDDD, например AB-1234): ZX-9999
Отказ: следующий код после 9999 не определен.
```
